# Установка через Dockploy

Пошаговая инструкция для разворачивания `dtyapkin/gamehub` на VPS.
Проверено локально: чистый клон без авторизации → сборка обоих образов →
три контейнера healthy. Дальше нужна только настройка Dockploy.

> Названия пунктов меню в Dockploy немного отличаются от версии к версии.
> Ориентируйся по смыслу, а не по подписям.

---

## Шаг 0. Домен

Сделай A-запись домена на IP сервера и дождись распространения:

```bash
nslookup example.com
```

Пока TTL не протух, можно двигаться дальше — записи понадобятся позже.

---

## Шаг 1. Создать сервис

1. Открой Dockploy, раздел **Services** (или **Applications**) → **Create Service**.
2. Тип сервиса: **Docker Compose**.
3. В качестве источника — **Git Repository**:
   - провайдер GitHub
   - репозиторий `dtyapkin/gamehub`
   - ветка `main`
   - root directory — пусто (корень репозитория)
4. Сохрани. Dockploy склонирует репозиторий.

Авторизация не нужна: репозиторий публичный, сабмодулей нет.

---

## Шаг 2. Переменные окружения

`.env` в репозитории нет (он в `.gitignore`), поэтому секреты надо задать
вручную.

Сгенерируй блок на сервере:

```bash
for k in POSTGRES_PASSWORD APP_KEYS API_TOKEN_SALT ADMIN_JWT_SECRET \
         TRANSFER_TOKEN_SALT JWT_SECRET ENCRYPTION_KEY; do
  printf '%s=%s\n' "$k" "$(openssl rand -base64 48 | tr -d '\n')"
done
```

Скопируй вывод и вставь в раздел **Environment** сервиса. Плюс добавь
вручную:

```env
POSTGRES_DB=gamedoor
POSTGRES_USER=gamedoor
BACKEND_PORT=1337
FRONTEND_PORT=3000
STRAPI_API_URL=http://backend:1337

# домен из шага 0
STRAPI_PUBLIC_URL=/
STRAPI_ADMIN_URL=/admin
CORS_ORIGIN=https://example.com
```

Это полный список: 15 переменных, которые compose читает из окружения.
`STRAPI_BEHIND_PROXY` и `STRAPI_TELEMETRY_DISABLED` в Environment
задавать не нужно — в `docker-compose.yml` они уже зашиты константой
`"true"`.

### Про `BACKEND_PORT` и `FRONTEND_PORT`

Это порты **на хосте**, а не внутри контейнера. Внутри контейнеров всегда
1337 и 3000, и их менять не нужно: compose пишет
`"${FRONTEND_PORT}:3000"` — слева хостовый порт, справа контейнерный.

Значения 3000 и 1337 — дефолты, и на сервере они часто уже заняты
чем-то другим. Деплой упадёт с
`Bind for 0.0.0.0:3000 failed: port is already allocated`.

Проверь, что порты свободны, и подставь свои:

```bash
ss -tln | grep -E ':(3000|1337) '   # кто слушает

# подобрать свободный
for p in 3005 8080 9080 1339; do
  ss -tln | grep -q ":$p " || echo "$p свободен"
done
```

Проверено: при `FRONTEND_PORT=3005` и `BACKEND_PORT=1339` стенд
поднимается и отвечает, контейнерные порты остаются 3000 и 1337.

После смены портов в **Шаге 3** укажи новые значения в маршрутизации:
если домен идёт на frontend, порт там должен совпадать с
`FRONTEND_PORT`.

Про `CORS_ORIGIN`: замени на свой домен. Значение `*` открывает API с
любого сайта, поэтому compose требует эту переменную явно и не
стартует без неё. Если фронтенд и админка на одном домене за одним
прокси, CORS технически не нужен, но значение всё равно стоит задать —
тогда при неудачной маршрутизации ты получишь явную ошибку в консоли
браузера, а не молчаливый доступ.

---

## Шаг 3. Домен и маршрутизация

Добавь домен в раздел **Domains** и настрой правила. Сначала — вариант
«всё на одном домене» (рекомендую, compose под него настроен):

| Путь | Куда | Порт |
|---|---|---|
| `/admin`, `/admin/*` | backend | 1337 |
| `/api`, `/api/*` | backend | 1337 |
| `/uploads`, `/uploads/*` | backend | 1337 |
| `/` (остальное) | frontend | 3000 |

Правила добавляются отдельными строками для одного домена. Порядок
важен: более длинные пути должны быть выше, чем `/`.

**Альтернатива — два домена** (проще, если не хочешь возиться с
правилами путей):

| Домен | Куда | Порт |
|---|---|---|
| `example.com` | frontend | 3000 |
| `api.example.com` | backend | 1337 |

Тогда в переменных поменяй:

```env
STRAPI_PUBLIC_URL=https://api.example.com
STRAPI_ADMIN_URL=https://api.example.com/admin
CORS_ORIGIN=https://example.com
```

---

## Шаг 4. Задеплоить

Нажми **Deploy**. Сборка занимает 4–6 минут (два образа плюс админка
Strapi). Дождись, пока все контейнеры станут `healthy`.

---

## Шаг 5. Проверить

Открой в браузере и в терминале:

```bash
# админка и API
curl -I https://example.com/admin          # 200
curl -s https://example.com/api/ad-placements | head -c 200

# главная
curl -I https://example.com/                # 200
```

В логах сервиса ошибок быть не должно. Если админка после логина
редиректит на `http://backend:1337/admin` — не выставлены
`STRAPI_ADMIN_URL` / `STRAPI_BEHIND_PROXY`.

Первый вход в админку: Strapi спросит email и пароль администратора и
создаст его. На чистой базе это делается один раз.

---

## Шаг 6. Залить данные (если нужны рекламные слоты)

Права Public-роли на `ad-placements` (`find` и `findOne`) выдаёт
bootstrap при старте — на чистой базе это происходит само, руками
ничего делать не нужно.

Остаётся наполнить базу самими слотами: на чистом сервере она пустая,
и пока слотов нет, показывать нечего. Дампы намеренно **не** лежат в
репозитории: внутри них email администратора и хеши API-токенов,
публиковать их нельзя.

С локальной машины залей дамп на сервер:

```bash
scp dumps/strapi-20260928-144952.dump user@server:/srv/gamedoor/dumps/
```

Дальше на сервере:

```bash
cd /srv/gamedoor
docker compose exec -T postgres pg_isready -U gamedoor   # убедиться, что БД поднята
./scripts/db-restore.sh dumps/strapi-20260928-144952.dump gamedoor gamedoor
```

Третьим и четвёртым аргументом явно передай имя базы и пользователя
(`gamedoor gamedoor`, как в примере выше). Это важно: скрипт по
умолчанию читает их из файла `.env` в корне репозитория, а в Dockploy
переменные заданы через интерфейс и такого файла там не будет — без
явных аргументов скрипт подставит стандартные значения и не найдёт
базу.

Пароль для `pg_restore` не нужен: команда выполняется внутри контейнера
под локальным пользователем Postgres.

После восстановления проверь, что данные на месте:

```bash
docker compose exec postgres psql -U gamedoor -d gamedoor \
  -t -A -c "select count(*) from ad_placements"
```

Должно быть 84. В API отдаётся 42 — Strapi не отдаёт неопубликованные
записи, так что это норма.

> Путь к репозиторию Dockploy может отличаться от `/srv/gamedoor`.
> Посмотри его в настройках сервиса.

---

## Шаг 7. Обновление при новых коммитах

Dockploy сам подтянет изменения при **Redeploy**. Тома с базой и
uploads при этом сохраняются — данные не потеряются.

Перед обновлением можно снять дамп:

```bash
./scripts/db-dump.sh
```

Скрипт при отсутствии `.env` подставляет `gamedoor` / `gamedoor`, так
что в Dockploy он отработает без правок. Дамп останется на сервере в
`dumps/` — если нужна своя копия, забери его через `scp`, при
следующем деплое он может перезаписаться.

## Если что-то пошло не так

**Контейнер `backend` перезапускается по кругу**
Нет доступа к базе. Проверь `POSTGRES_PASSWORD` в Environment: он должен
совпадать с тем, что в `.env` на сервере, иначе Strapi не подключится.

**`port is already allocated`**
Хостовый порт из `FRONTEND_PORT` или `BACKEND_PORT` уже занят другим
контейнером или процессом. Найди, кто его держит, и смени значение на
свободное:

```bash
ss -tlnp | grep -E ':(3000|1337) '
docker ps --format '{{.Names}}\t{{.Ports}}' | grep 3000
```

Либо останови то, что занимает порт. После смены не забудь поправить
порт в маршрутизации домена из Шага 3.

**`CORS_ORIGIN is required in .env`**
Переменная не задана в разделе Environment. Compose специально не
подставляет значение по умолчанию, чтобы не открыть API наружу.

**Админка 404**
Обычно не отработала маршрутизация `/admin`. Проверь, что в правилах
путей есть и `/admin`, и `/admin/*`.

**Реклама не показывается**
Проверь, что на странице с рекламой есть блоки, а не пустота:
`curl -s https://example.com/ | grep -o 'R-A-[0-9-]*'`.
Если пусто — смотри логи `frontend`, там будет ошибка про
`STRAPI_API_URL`. Убедись, что переменная задана в Environment.

Отдельно про `403` вместо рекламы: если `curl` на
`/api/ad-placements` отдаёт 403, проверь, что в базе есть права
Public-роли:

```sql
select p.action from up_roles r
join up_permissions_role_lnk l on l.role_id = r.id
join up_permissions p on p.id = l.permission_id
where r.type = 'public' and p.action like '%ad-placement%';
```

Должны быть две строки — `find` и `findOne`. Если их нет, bootstrap не
отработал: проверь в логах `backend` строку
`[bootstrap] Public-роли выдано право`.

**Сайт открывается, но `/api` отдаёт 404**
Правило для `/api` настроено на frontend вместо backend, либо
пропущено. Правила путей в Dockploy применяются сверху вниз — более
специфичные должны быть раньше.
